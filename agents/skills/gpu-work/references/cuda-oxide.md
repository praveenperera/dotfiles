# cuda-oxide watch-outs

Traps that cost correctness or speed in cuda-oxide kernels, and the checks that catch them. The user maintains this file; during a task, log new traps in the decision log instead. Each entry gives the trap, the fix, and the commit it was seen at where a later commit may fix it. Recheck entries when the pin moves. A slowdown measured but not explained goes under an "Open slowdowns" heading with its suspects until a test confirms or clears it.

**Coverage:** sam3rs (about 50 kernels: elementwise, norms, convs, BF16 and TF32 flash attention) and whisperdrz (FP16 decoder and attention kernels, small-M `mma` linears, DTW, ECAPA2 side kernels), both on an RTX 5090 (sm_120). The sm_80 PTX tier has run only on the 5090, never on Ampere. Not yet exercised, so expect unlisted traps: atomics, grid-wide reductions, cooperative launches, TMA, `wgmma`, FP8, clusters.

## Setup

The pin and the crate layout are in SKILL.md "Kernels".

- **Moving the pin:** rebuild at both pins, run `sass_mix.sh` over every kernel, and time any kernel whose registers moved. `4c0182cd5` and `a5c86a293` carried an unnoticed 3.7% flash-attention slowdown (the `convergent` entry below).
- The backend cache in `$CARGO_HOME/cuda-oxide/` has one slot, rebuilt whenever a project's `cuda-device` resolves to another commit, hence the project-owned `CARGO_HOME`.
- `cargo oxide build` rebuilds a missing or stale backend, so build scripts needn't call `setup`. `setup` rebuilds even a fresh cache from your `cuda-device` commit, and refuses when `CUDA_OXIDE_BACKEND` or `.cargo/cuda-oxide.toml` pins the backend. `build` rewrites the PTX every run only when the crate root is `src/lib.rs` or `src/main.rs`; otherwise check the PTX timestamp.
- **Use the toolchain's own llc, and fail when it's missing.** cuda-oxide silently falls back from `CUDA_OXIDE_LLC` to the sysroot llc, then `llc-23`…`llc` on PATH. llc-21 brings traps LLVM 23 doesn't have and made `flash_attn_rpb_d32` 6% slower, and a toolchain reinstall without `llvm-tools` moved 31 of 66 sam3rs kernels with no source change. Set `CUDA_OXIDE_LLC=$(rustc +T --print sysroot)/lib/rustlib/<host>/bin/llc` and fail if absent (sam3rs `scripts/build-ptx.sh`). Don't inherit an env file's `llc-21`. Keep the pinned toolchain out of rustup cleanup crons; reinstalling it needs `rustup component add rust-src rustc-dev llvm-tools --toolchain T`, since `cargo +T` ignores the components list.
- Host `cargo check` of the kernel crate needs `RUSTC_BOOTSTRAP=1`, the project's `CARGO_HOME` and `+<toolchain>`.
- The PTX ISA `.version` sets the minimum driver; check it in the build script (7.0 for sm_80, 8.7 for sm_120).

## Speed traps

- **Hot generic `#[device]` helpers need `#[inline(always)]`.** Without it, a large body stays a `.func` and its pointers arrive generic (generic `LD` instead of `LDS`/`LDG`: `flash_combine_d32` +72%). `#[inline(never)]` keeps a `CALL`. A generic `#[inline(always)]` helper in a kernel-less crate, instantiated only from host code, is dropped at release opt.
- **A borrow (`mir.ref`) of a local inside a loop allocas at the use site**, which LLVM treats as dynamic: no inlining, and SROA leaves it on the stack. An unexplained `.func` or frame: look for an `alloca` outside `entry:`.
- **`Zip` over a slice and a view iterator is 2.15x slower than a counted loop** (two exits, so it stays rolled). Use a counted loop over views; `zip_exact` is fine on LLVM 23.
- **An inline helper returning `Option<(struct, views...)>` put the payload on the stack** (304-byte frame in every sam3rs flash kernel; not rechecked at the pin). Return a plain tuple and `unreachable_unchecked()` past one up-front check.
- **Register arrays indexed by a rolled loop's counter go to `.local`.** A `[F32x4; N]` row cache or `.0[e]` needs constant indices, so the loop must fully unroll; an 8-step pass calling `expf` stays rolled. Filling an array through `iter_mut().enumerate()` also lands it on the stack. Put `#[unroll]` on every loop that indexes a register array, or build vectors with array constructors. Optimized builds warn only for literal bounds ("could not be promoted to registers"), so check `ptxas -v` otherwise.
- **Integer division:** 64-bit `/` and `%` (`i64` from `long long`, and every runtime `usize`) compile to ptxas's divide routine, a SASS `CALL`. Use 32-bit coordinates (`thread::index_1d_u32`, `element_thread32`, `#[launch_contract(coordinates = u32)]`), shifts or constant divisors: 20-70% fewer instructions. Don't derive a row length as `x.len() / gridDim.x` in a block-per-row kernel; pass it as a param (layernorm 3% faster).
- **Rust's panic checks compile to traps.** `clamp` asserts min ≤ max and `/` checks for zero, each a trap even with block-uniform bounds or a later check that rejects zero. Use `max` then `min`, and divide by `x.max(1)`. A trap that depends on the thread marks the warp divergent, so ptxas wraps every later shuffle and `mma` in WARPSYNC (SASS `CALL`s on sm_80); in warp-cooperative kernels check once with a block-uniform condition and index unchecked after.
- **Bounds-checked `slice[i]` in a loop can stop unrolling** (14 loads in flight became 2, +2.9%; a naive GEMM 2.4x slower) and costs registers. Read through `MatrixView32`/`RowView32`, whose `get(i)` checks once.
- **Block-uniform checks before the first load cost 4-7% in short block-per-row kernels** (`88e52d117`). Fold every check into one non-short-circuit condition (`a & b & c`, one `return`) and read through a row pointer it covers. `ld.global.nc` and `get(c).unwrap_or(0.0)` measured 0%.
- **`f64::max`/`min` (and `libm::fmax`/`fmin`, and `f32` on the libNVVM route) compile to compare + select.** On the default route `f32::max`/`min` and `warp::reduce_max_f32` are one instruction.
- **`#[unroll(N)]` partially unrolls block-stride loops**: a counted-up `<`/`<=` loop with a runtime start, a positive constant or loop-invariant step (`i += blockDim_x()`) and a bound recomputed from fixed values. A `match` in the body is fine; a `break` isn't. Full `#[unroll]` needs a constant start and step.
- **`DisjointSlice` turns a scatter into a gather that can read strided** (a `[14400, 8]` transpose 1.58 vs 1.11 µs). Keep the scatter through `as_mut_ptr()` with a SAFETY comment, or use a shared-memory tiled transpose.
- **With llc-21 only:** a pointer merged with null through `if`/`select` (a view or `RowView32::empty()`) turns loads generic; keep optional inputs as empty slices and test `is_empty()`. `for x in arr` by value keeps the array on the stack.
- **PTX can change without a code change.** Moving code into shared helpers can shift SASS with no spills (+8 instructions in the BF16 flash kernels). Shared statics and device globals are named from a hash of the symbol, and `const` globals from their contents, so adding or reordering kernels doesn't rename them. Labels, `// @<name>` comments and keyless `__shared_mem_<n>` still move. Normalize those (`PW/ops/sam3rs/hill-climb/ptx_same.py`) before calling a kernel changed, and when a kernel must stay unchanged, give the new kernel its own copies and diff the old kernel's PTX to byte-identical. A static with two same-type `SharedArray` or `Barrier` fields at one offset is refused; give each its own static.
- **`cvt.rna.tf32.f32` costs 3 instructions per value on sm_120** (a NaN/Inf `FSETP` guard, an add, a mask), the same as nvcc.
- **For `ldmatrix`, prefer `ldmatrix_*_shared_u32` with a per-lane u32 address computed once.** A runtime-stride usize form costs about 16 setup instructions and 4 registers, with no measured time.
- **Special-register reads must stay `convergent`.** Without it (`acd66a84f`), EarlyCSE merges `tid.x` reads and LICM hoists the dependent staging and `ldmatrix` addresses: flash kernels gained about 50 registers and ran 3.7% slower. The fork restored blanket `convergent` at `b1e94cedf`; if a pin drops it, time the flash kernels against the build before.
- **Under one wave, ptxas can save registers for occupancy the grid never uses** and serialize loads to fit (`flash_attn_rpb_d32`, 0.53-0.66 waves: 96 registers, bias loads two at a time). Editing `.minnctapersm 1` (what `#[launch_bounds(128, 1)]` emits) or `.maxnreg 128` into the PTX gave 115 registers and 2.7% ahead of nvcc; the attribute itself wasn't timed. Try the min-blocks bound when a latency-bound grid is under a wave at every deployed shape; above a wave, time it. Diagnose from scoreboard waits in SASS, not load counts.

## Correctness traps

- `convert::f32_pair_to_packed_bf16` **truncates**; `cvt_bf16x2_f32` rounds to nearest even.
- **An unchecked read evaluated before the check that proves it** (`x.unwrap_or(unsafe { *w.get_unchecked(c) })`, or a `let` above `if w.is_empty()`) is UB on a short slice. Keep each unchecked read inside its proving branch.
- **Take the index before the output witness, and the read after it.** `let v = x[t.get()]` above `element_thread32(t)` runs on tail threads and traps. Use `let i = t.get() as usize`, then the witness, then the read.
- **The launch contract is only checked by cuda-oxide's own launcher.** Another host (cudarc, the driver API) must keep `grid x block <= 2^32` for 32-bit coordinates and pass a length after every slice pointer. A `BlockRows` slice is (pointer, u64 length, u32 width).
- A `const` reference or promoted borrow is a read-only global: a device fn may return it, but only read through a `*mut` cast from it.
- A const, table or static holding a pointer to shared memory (`SharedArray`, `Barrier`) is refused; pass shared pointers as arguments or build the value at run time. A shared pointer stored through a generic place is widened to generic.
- **A kernel that appends to a cache it reads in the same launch** must read the new keys from the source rows, never from the cache.

## API gaps and limits

- `#[unroll]` only works inside `#[kernel]`/`#[device]` bodies; in a `macro_rules!` body or plain helper, start the loop body with `__unroll_config::<N>()` (0 = fully), and recheck it on pin moves (it's undocumented). An inner `__unroll_config::<0>()` loop starting at an outer loop's variable stays rolled: loop `i` over `0..N` and use `kk = c0 + i`.
- An unroll clones at most 65,536 operations, counted after inner loops expand; past it the loop stays rolled with a warning naming the `#[unroll(max_ops = M)]` it needs. Big unrolls still cost (255 registers, 1288 B spilled, 258 s to lower), so check `ptxas -v` or split the loop.
- `ThreadIndex32` is not `Copy`: each output `DisjointSlice` needs its own witness from `thread::index_1d_u32(lc)`.
- Block-per-row kernels take `DisjointSlice<T, BlockRows>` with the width bound on the host by `cuda_host::RowWidth::new(&mut buf, width)`. `out.block_row32(lc)` gives block b row b (`None` for the whole block on a partial row or width 0), and `row.thread_columns()` yields witnesses with `read()`, `write()`, `column()`. An in-place kernel reads through those witnesses; also taking the buffer as `&[T]` is UB.
- A `DisjointSlice` is written only at the thread's own index; a thread with two outputs takes a second witness or writes one combined buffer.
- Wide loads and stores come from alignment, not asm: `vector::F32x4` (or a `repr(C, align(16))` type) in a slice, `DisjointSlice` or `SharedArray`, or `vector::as_vectors`. Reading only some lanes narrows the load.
- No `f16` or `bf16` value type on stable: the `f16`, `f16x2`, `bf16` and `bf16x2` intrinsics carry `u16`/`u32` bits. Wrap them in a newtype using `convert` (`cvt_f32_f16x2_lo`, `cvt_f16x2_f32`).
- No `static mut SharedArray` in generic fns (E0401): declare tiles per kernel and pass pointers, or use `DynamicSharedArray`. No `[T; D / 16]` in generics: pass the derived length as another const param.
- Math: use `float::fma_rn_f32` or `a * b + c` (contracts to `fma.rn`), not `f32::mul_add`. `libm::erff`, `sqrtf` and 120 other libm exports lower to libdevice. libm has no rsqrt: use `float::rsqrt_approx_f32`, or declare `extern "C" fn __nv_rsqrtf` to match nvcc's `rsqrtf`. `__CUDA_FTZ` reflects to non-FTZ, nvcc's default.
- Optional output: pass `DisjointSlice::empty()` or `Default::default()` by value; a reference to a `const` `DisjointSlice` doesn't compile. An associated `const` struct holding `&[T]` fails codegen; build it in an `#[inline(always)] fn` with inline `&[]`.
- `launch_contract(block = ...)` emits `.reqntid` only, since ptxas forbids it with `.maxntid`.
- Tensor-core wrappers: `cuda_device::wmma` has `mma_m16n8k16_f32_bf16`, `_f32_f16`, `_f16_f16`, `mma_m16n8k8_f32_tf32`, `mma_m16n8k4_f32_tf32`, `ldmatrix_*` and the `mma_frag` layout helpers. Search the crate, including `generated/`, before writing `ptx_asm!`. `ldmatrix_x4_shared_u32` over FP32 rows (stride D + 4 words) gives exactly the m16n8k8 TF32 A/B fragment, and the S accumulator serves as the P @ V A fragment as `{s0, s2, s1, s3}`.
- A host launching slice-ABI kernels should check its arguments against each `.entry` param list parsed from the loaded PTX, once per kernel. Don't probe `cuFuncGetParamInfo` past the last param (compute-sanitizer flags it); `cuFuncGetParamCount` needs CUDA 13.2.
- `#[kernel] pub unsafe fn` with raw pointers and scalars exports a C-like entry, so hosts written for CUDA C++ kernels need no launch changes.

## Checks on every build

- `scripts/sass_mix.sh REF.ptx NEW.ptx [ARCH] [KERNEL...]` (CPU only): calls left in each PTX, then per kernel the registers, stack, spills, SASS instruction count and trap opcodes (generic `LD`, `FSETP`+`FSEL`, `LDL`/`STL`). With no kernels, every kernel whose registers or spills changed.
- `scripts/nsys_kernel_diff.py CTL.sqlite[,...] EXP.sqlite[,...] [N]`: per-kernel GPU time of two builds from nsys SQLite exports, both profiled through the queue with the same command, interleaved.
- No `call` in the PTX; fail the build on one. Check PTX, not SASS: ptxas adds SASS `CALL`s for the IEEE f32 division slow path (`1/x`, `x/n`) even when everything is inlined. Other SASS `CALL`s are real: integer divides or divergent-shuffle fallbacks.
- ptxas `-v`: no unexpected spills or frames (a 32-byte frame with `sinf`/`cosf` is libdevice's slow path, as with nvcc).
- A refactor with byte-identical PTX is safe; diff it. When porting or changing codegen, compare SASS opcode counts per kernel, and run an nsys per-kernel diff plus an A/B in every precision mode: parity and sanitizers miss speed regressions.
