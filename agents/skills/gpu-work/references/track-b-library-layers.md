# Track B: replace library layers

Writing custom kernels for layers cuDNN or cuBLAS already runs. Shorthands as in SKILL.md.

- **Reverse-engineer the library first**: its algorithm query, kernel names and bitwise forensics on small cases. Match or beat that structure; tuning a different structure plateaus.
- **The library picks a different algorithm per device and batch, so library-relative gates flip.** On sm_120, cuDNN ran FP32-exact paths inside "TF32 mode" for C32 and stride-2 convs; on Ada at b1 it used real TF32 and was slower than its own FP32. Record the pick per device (cuDNN logging shows it), bound error as a ratio to the library's own error against f64, and use a small explicit per-device choice of our path where numerics differ.
- **Peak fraction isn't the target**: near-peak FP32 convs still lose to Winograd. Beating a library on datacenter parts needs algorithmic changes (Winograd, split precision, INT8 tensor cores), because on an A100 TF32 runs at 8x FP32 and INT8 at 32x. On GeForce, dense TF32 runs at about the FP32 rate, while INT8 runs at about 8x on Ada. A build 1.4x slower than cuDNN on an A100 had 14 early convs on scalar FMA where cuDNN used TF32; fixing that made it 1.17x faster.
- **Aim custom kernels at small and odd shapes**, where library heuristics lose (fbank DFT 1.7-2.4x, wide ResNet convs 167 of 176 cases on Ada). Cap attempts on the rest: equal-channel TF32 convs on an A100 stayed at 0.58-0.97x after two tries and went back to cuDNN.
- **Keep the harness rough, and cap it by the kernel work**: f64 or CPU reference, timed A/B on representative shapes, end-to-end check on a fixed file set. A 5-day proof harness merged one PR with no end-to-end number, then the rough check shipped more in 8 hours. Add proof machinery only for risks that check can't see, time-boxed, with one external audit at a freeze point.
- **Prove each shipping gate with a planted bad kernel** that must fail that exact gate: BF16-rounded input, correct at one batch only, library fallback, skipped tail, FP atomic accumulation, deliberately slow. Fallback and slow keep the numeric output, so they need a profile gate (no library calls inside candidate ranges) and a speed gate.
- **Scope sanitizers to your own kernels, and hand-audit what they miss.** A cuDNN persistent-RNN racecheck ran 1 h 43 min without finishing. initcheck covers global memory only and racecheck shared memory only, so shared-memory initialization needs a hand audit. A different-family audit caught a memory-ordering race, a cooperative-grid deadlock and an INT8 scale overflow to NaN that passed every gate.
- **Check that the loader runs the artifact you qualified.** Exact-arch cubins outranked the qualified PTX and would have sent every RTX 50 layer back to cuDNN. Short profile traces miss library calls made during warm-up and graph capture.
- **Gate finite-in, finite-out on extreme finite and special values.** A fallback dividing by a stored scale turned activations near 2^117 into Inf. Truth for non-finite inputs is f64, not cuDNN, whose Winograd makes its own inf − inf NaNs; treat non-finite weights as a typed plan-time decision, never a silent zero.
- Declare coverage per (layer, batch class, math mode, device), and leave undeclared cases on the library.
- Scope speed claims to measured hardware. Never promise "every GPU".
- Call FP32-accurate schemes such as Ozaki by their real contract, not "exact FP32".
