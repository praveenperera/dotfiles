# Track C: native model runtime

Porting a whole model off PyTorch or ONNX Runtime. Shorthands as in SKILL.md.

- **Know which kind of model it is.** Step loops, many small ops and multi-stage pipelines gain 20-30x over a generic runtime. A GEMM-bound encoder gains about 1.05-1.1x on kernels alone, and the win is in the glue and in fusing attention and conversions (SAM 3's encoder reached 1.27x over PyTorch BF16 that way). Do the floor arithmetic first.
- **Check the workload size and the cheap upstream fix before a go.** A model whose consumers spend 10-25 GPU-minutes in total is a no-go. One pipeline's 58 to 32 s came from a policy patch (keep VAE caches on the GPU), not kernels, and an open upstream patch (KV cache, CUDA graph, MPS) already took another from 12.1 to 70.4 pages/s. Baseline against PyTorch with `torch.compile` and graphs, not a slower incumbent runtime: ORT-based runtimes of one model ran 2-9x slower than stock PyTorch.
- **Where the time usually is:** host round trips and re-uploads, CPU fallback ops, one launch per op, host-driven decode loops with a sync per step, CPU glue, and stages run one after another. What pays: tensors kept on the GPU, CUDA graphs where the GPU idles, the decode loop as small fused kernels, host prep overlapped with the GPU, batching, and glue fused into neighbors.
- **Once kernels are fused, profile host idle time before more kernel work.** A one-hour call was 30% idle on 66 ms of window prep per batch; a producer thread, an O(n²) merge fix and four prep threads took it from 1,260x to 1,683x real time with byte-equal output.
- **Bound a persistent decode kernel before writing it.** A graph of small fused kernels is the baseline: a 700-line persistent cooperative decode tied it at b1, lost at b8 (9.8 vs 7.3 ms), and was parked. Steps took 54 µs, not the estimated 24, because the model skips frames, and 39% was one thread folding 170 block partials serially.
- **Look for work the structure makes redundant.** When every cross-attention layer's K/V are linear maps of one encoder output, absorbing the weights cuts decode bytes. When values are a linear projection of a narrower input with nothing between, fold `v_proj` into `o_proj` on the host in f64 and attend at the narrower width (64 instead of 256 in SAM 3's memory attention). Reuse K/V a previous stage already cached. Price each at the real token counts first.
- **Count blocks per SM before judging a fusion, and gate the fused path on every dimension it depends on.** A fused attention with 32 blocks for 170 SMs lost until a 16-way key split made it win. Another fit one wave at 300 frames and needed two at 375, so it won 5-19% on batches and short clips and lost up to 15% on long single clips; dispatch on both batch and length.
- **Choose precision per layer and test each contract.** BF16 tensor cores need BF16 storage, conversions are a hidden cost, and a global math mode leaks into layers promised FP32. Convert a sublayer only where the chain stays BF16: a BF16 FFN won x1.055 while its attention projections lost x0.991 to conversions. Check the framework's defaults per op family (cuDNN convs default to TF32, matmul doesn't). Price FP8 with a fake-quant pass on the end gates before building it, and probe its rates rather than assume them.
- **Low-bit weights cut download size, not VRAM, and rarely speed at batch 1.** FP8 and NVFP4 saved 0.4-0.7 GB of a 7 GB peak, and FP8 ran slower than FP16 on single utterances.
- **Time cuBLASLt's top candidates per shape and precision on small or odd shapes.** Heuristic pick #0 was best on big GEMMs, but other candidates were 1.10-1.58x faster on 32-row, 201-row and conv-tap shapes. Keep a pick only when it wins by over 5%, which kept output hashes identical across processes, and budget the first-call tuning cost (+100-300 ms).
- **Make reductions deterministic before relying on a hash gate.** Float `atomicAdd` group-norm partials flipped mask pixels between identical runs; fixed-order partials plus a reduce kernel cost nothing measurable. Fingerprint only the stage a guard protects.
- **Check parity per layer, not just at the output.** Deep stacks amplify rounding. Compare each kernel with f64 on its exact rounded inputs, and gate a layer whose framework error is zero by construction against f64, not a multiple of zero. On a deep stack, judge chained error against the worst of several exact-in-real-arithmetic reference reruns. Match the framework's arithmetic, including FMA contractions (`torch.linspace` is `start + i*step` as an FMA on CUDA).
- **Gate reduced precision per stage, and around argmax picks.** Give a BF16 backbone and heads on exact inputs their own bounds. Excuse a near-tie flip only within a margin, cap how many, and keep the mean limit on every frame. Check two reduced-precision paths against a common truth, not each other.
- **Make parity fixtures trustworthy.** A stage test that runs only when its fixture key exists passes on a dump without it, so count each stage's checks. Assert mask lengths before an IoU and fail non-finite scores. Clone in framework hooks, since saved tensors see later in-place edits. Feed the reference's decoded audio or image to parity tests, golden-test the tokenizer including special tokens, check weights against a committed schema, and reject config options the engine doesn't implement.
- **Pin the vendor library versions the reference uses** when parity is tight: load the framework's exact cuBLAS build, since another version may pick different GEMM kernels.
- **The speed phase is a hill climb**: open `PW/playbooks/gpu-hill-climb.md` once the parity gate passes.
- **Price a second stream or engine by timing the real work list on N of them in one queue job**, not from idle gaps; the share of kernel time in full-wave grids predicts the gain. The default stream priority is the lowest, so raise decode's priority for a background stream to rank below it. `cuMemcpyDtoHAsync` to pageable memory blocks until its stream drains, and other threads' pageable copies queue behind it; use pinned buffers. Large result copy-out is the exception: for 12 MB of masks, pinned staging lost (x0.96-0.99), while faulting the destination pages in on a helper thread during GPU work won x1.068. A step result that sets the next batch's composition can't move off the critical path without changing output.
- **Bound shape caches by bytes** and share scratch across shapes, then count misses before blaming kernels. Warm a shape-cached runtime to a fixed point before timing. Serialize load, capture and teardown with one process-wide lock, and test concurrency under full CPU load. Capture CUDA graphs at load, before other models launch work, with static buffers per thread; never share one graph across threads. In PyTorch, capture under `torch.no_grad()`.
- **Build the safe Rust layer early:** `Pod`-only transfers, host buffers kept alive through async copies, buffers that keep their stream alive, async copies that accept only the calling handle's buffers, loader errors instead of panics, geometry validated at the API boundary, and every GPU step checked before its results update host state.
- **Time results through the binding users call, and hand large host outputs over without copies**: one contiguous, recycled buffer viewed through the buffer protocol, not numpy copies, which stall on huge-page compaction. Count `compact_stall` in `/proc/vmstat` around slow calls.
- **Time recurrences inside a CUDA graph, and check tiny ones against the CPU.** CUDA-event timing of a step reads host launch time; some tiny steps are faster on the CPU.
