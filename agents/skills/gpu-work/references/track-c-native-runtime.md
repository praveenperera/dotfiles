# Track C: native model runtime

Porting a whole model off PyTorch or ONNX Runtime (speakrs, scriptrs, sam3rs). `R` = `~/code/research/gpu-kernels/`, `PW` = `~/code/private-workbench/`.

- **Know which kind of model it is.** Step loops, many small ops and multi-stage pipelines gain 20-30x over a generic runtime (speakrs). A GEMM-bound encoder gains about 1.05-1.1x on kernels, and the win is in the glue: SAM 3 prompts gained 1.3-15x. Do the floor arithmetic first. (`~/code/research/inference/specialized-model-runtimes/generic-vs-specialized-kernels.md`)
- **Where the time usually is:** host round trips and re-uploads, CPU fallback ops, one launch per op, host-driven decode loops, glue on the CPU, and stages run one after another.
- **What paid across the ports** (not ranked): keeping tensors on the GPU, a CUDA graph per shape where the GPU idles (check GPU-busy first), the decode loop as a graph of small fused kernels, host prep overlapped with the GPU, batching, and fusing glue into neighboring kernels.
- **Choose precision per layer and test each contract.** BF16 tensor cores need BF16 storage, format conversions are a hidden cost, and a global math mode leaked into layers promised FP32. (Lessons §7)
- **Check parity per layer, not just at the output.** Deep networks amplify rounding (about 3x per layer in the last four Parakeet layers). Compare each kernel with f64 on its exact rounded inputs, and check that the f64 reference matches the framework. (Lessons §8)
- **Fail closed on inputs:** check weights against a committed schema, have the loader reject config options the engine doesn't implement, golden-test the tokenizer against upstream including special tokens, and feed the reference's decoded image or audio to parity tests. (Lessons §7, §10)
- **The speed phase is a hill climb.** Once the port's parity gate passes, open `PW/playbooks/gpu-hill-climb.md` before the first speed change and follow its nsys-then-ncu loop. The sam3rs tracker climbed from nsys alone and picked one step on a wrong diagnosis (see SKILL.md "Diagnose before you pick a design")
- **Bound shape caches by bytes** and share scratch across shapes, then count cache misses before blaming kernels. Serialize model load, capture and teardown with one process-wide lock, and run concurrency tests under full CPU load. (Lessons §8)
- **Build the safe Rust layer early:** `Pod`-only transfers, host buffers kept alive through async copies, buffers that keep their stream alive, loader errors instead of panics, and geometry validated at the API boundary. (Lessons §7, §9)
- **Time results through the binding users call, and hand large host outputs over without copies.** A Rust bench that drops its results never sees what a Python caller pays. In sam3rs, `bytes` plus numpy `astype(bool)` copies of 4-5 MB masks cost 10-1100 ms a call, because numpy asks for transparent huge pages on arrays of 4 MB or more and direct compaction stalls on fault. Fresh pages also cost about 0.23 ms per MB to fault in. Return one contiguous buffer that numpy views through the buffer protocol, and recycle dropped buffers: a 27-mask box went from 249-319 ms to 14 ms. Count `compact_stall` in `/proc/vmstat` around slow calls (`~/code/research/inference/specialized-model-runtimes/sam3rs-decisions.md`, 2026-11-01)
- **Time recurrences inside a CUDA graph, and check tiny ones against the CPU.** A CUDA-event timing of cuDNN's BiLSTM read a flat 8 µs a step from batch 1 to 32; that was host launch. Inside a graph the same step took 2.8 µs at batch 1 and 5.6 µs at batch 8, where cuDNN swapped its GEMV for a slower tensor-core GEMM (Kokoro, `~/code/research/inference/specialized-model-runtimes/kokoro-baselines-2026-11-01.md`). A Silero VAD step was faster on the CPU than as a graph launch.
- **Gate reduced precision per stage, and around argmax picks.** A BF16 backbone already differs from FP32 by 1-3e-2 at its output while heads on exact inputs stay under 5e-3, so one bound either hides head bugs or fails on the backbone: give each its own. A candidate choice (multimask argmax) flips between modes on near-ties; excuse only frames whose top two predictions are within a margin from the worst-frame limit, cap how many, and keep the mean limit on every frame (sam3rs video, `~/code/research/inference/specialized-model-runtimes/sam3rs-decisions.md`)
- **A stage test that runs only when its fixture key exists passes on a dump without it.** Count each stage's checks and fail when one never ran. In the same way, assert mask lengths before an IoU and fail non-finite scores, which otherwise read as "absent" and score IoU 1
- **A framework hook that saves a tensor without cloning sees later in-place edits.** SAM 3 adds the no-object embedding to the memory encoder's output in place after the hook ran, so the fixture holds the edited tensor. Clone in the dump hook, or mirror the edit in the stage test
