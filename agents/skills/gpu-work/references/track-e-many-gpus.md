# Track E: many GPUs or rented boxes

Supporting several architectures, or working on vast.ai and similar boxes. Shorthands as in SKILL.md.

- Rent one GPU per target generation early; each finds bugs and losses the others can't.
- **Qualify per SM count, not just per compute capability.** A win qualified on a 70-SM RTX 5070 Ti lost on a 36-SM 5060 Ti and was pulled for cc 12.0, and Ada's 34 SMs flipped b1 layers to 0.73-0.98x. Qualify the smallest and largest card of a family, or add an SM-count bucket. `CUDA_MPS_ACTIVE_THREAD_PERCENTAGE` (about 21% for 36 of 170 SMs) approximates a smaller card, but bandwidth and L2 stay large, so memory-bound cases look optimistic.
- **Strategy differs by GPU class.** On GeForce, dense TF32 runs at the FP32 rate (quoted TF32 figures are often sparse), so it wins only by efficiency, and 3xTF32 runs at a third of FP32. On an A100, TF32 is 8x FP32 and INT8 32x.
- Size shared-memory tiles for GeForce: sm_86, sm_89 and sm_120 have 100 KB an SM and 99 KB a block, against 164-227 KB on A100 and H100. 50 KB is the most that fits two blocks an SM.
- Profile the whole pipeline on each new GPU before optimizing; libraries pick different paths per device.
- **Look for address-space bugs on a second architecture.** A shared pointer truncated to 32 bits ran clean through 21 sanitizer runs on sm_120 and gave 8,943 invalid shared writes on Ada; lint PTX for `cvta.shared.u64` feeding `cvt.u32.u64`. A sticky error from your kernel can surface later as a library error (`CUDNN_STATUS_INTERNAL_ERROR` at handle destruction): rerun with `CUDA_LAUNCH_BLOCKING=1` and memcheck before blaming the library.
- Cooperative grids start differently by architecture and can deadlock under MPS; budget joint residency against the context's SM count and fall back to sequential launches. Keep a private MPS pipe directory short (`mktemp -d /tmp/mps.XXXXXX`): the control socket path caps at 107 bytes, and `nvidia-cuda-mps-control -d` exits 1 with empty logs past it. Mixed-size loads and stores are a data race. Always use `cvta_generic_to_shared_u32`.
- **Measure the network before installing anything.** One A100 stalled 56 minutes on apt at 0.24 MB/s and was destroyed; gate on a quick transfer (40 MB in under a few seconds). Cap shared uploads at about 70% (`--bwlimit`), and start GPU work that needs few assets while big uploads run, gated on marker files.
- Billed boxes must never idle: smoke-test the package on a cheap box, bootstrap only the toolchain, cap uploads, and pull evidence on a schedule. Plan for credit and host loss: when credit runs out every box stops, and a restart keeps `/workspace` but a host can vanish. Poll an offline box for a bounded time, then replace it, and have workers write resume notes before a long box job.
- **Shared-box hygiene:** one SSH ControlMaster per box (24 parallel sessions hit sshd's limit) with its `ControlPath` in a mode-700 directory such as `~/.ssh/cm/%C`. Never hold the GPU lock for CPU-only work, keep holds to about 4 minutes, and rent a second box when more than two workers need timing at once.
- **Managed GPU platforms (Modal, Beam) are for correctness and CPU builds, not timing or counters.** Counters need host-level access (`NVreg_RestrictProfilingToAdminUsers=0` or `CAP_PERFMON`) that container root doesn't give. Name the exact SKU (`A100-40GB`, not `A100`).
- Never put secrets or agents on a rented SSH box. Wrap GPU work in a shared flock, kill only PIDs you started, and wipe the box when done. On managed platforms, the scope of platform-internal credentials is unconfirmed.
