# Technical document modes

Choose the mode from the reader's need. A document can link to another mode, but it should not switch jobs without warning.

## Tutorial

A tutorial helps a learner gain skill by completing a guided task.

- State what the reader will build
- Give a working result early
- Keep the path linear
- State the expected result after important steps
- Link to explanations instead of interrupting the lesson

## How-to guide

A how-to guide helps a competent reader complete one real task.

- Name the goal in the title
- Start with prerequisites and the common path
- Use direct commands
- Include decision points only when the reader must choose
- Link to background and complete reference material

## Reference

Reference material supports accurate lookup during work.

- Mirror the structure of the system or API
- State facts, inputs, outputs, defaults, limits, and errors
- Keep opinions and teaching out
- Generate from authoritative schemas or code when practical

## Explanation

An explanation helps the reader understand why a system or decision has its shape.

- Bound the topic
- State the problem and constraints
- Explain decisions, alternatives, and tradeoffs
- Separate direct evidence from inference
- Link to procedures and reference details

## Global English checks

- Keep `only`, `not`, and similar modifiers next to the words they change
- Give every pronoun one clear noun
- Break long noun strings into clauses
- Repeat the noun when a synonym would make the reader re-identify it
- Use a full verb in each clause
- Replace slashes with the exact relationship, such as `and`, `or`, or `both`
- Use periods instead of semicolons or dash punctuation
- Keep articles and connector words when they prevent a second reading
